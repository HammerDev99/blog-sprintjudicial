¿Por qué el código de AgilEx es público?

Open source en software judicial como acto de rendición de cuentas

Un funcionario judicial que usa AgilEx no tiene forma de saber qué hace el ejecutable que descargó, a menos que pueda leer el código fuente. El archivo AgilEx_by_Marduk.exe que llega a su despacho es un binario opaco. PyInstaller empaqueta Python, dependencias y recursos en un solo archivo que no se puede abrir y leer como se abriría un documento Word. La firma digital Authenticode SHA256 garantiza que el binario no fue modificado después de que lo firmé, pero no dice nada sobre qué hace el código que está adentro.

Publicar el código en GitHub no resuelve ese problema del todo, porque pocos funcionarios van a leer Python. Pero sí hace algo distinto, que es dejar el código auditable para quien pueda leerlo.

Ese if/else estaba en la vista, en el controlador y en partes del modelo porque nadie había decidido todavía a quién le correspondía saber qué modo estaba activo. Funcionaba. Era difícil de mantener desde el primer día.

La decisión de reescribir esa lógica fue la que convirtió AgilEx de un script que yo podía operar a una herramienta que otra persona podía sostener.
